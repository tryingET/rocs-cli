# Problem brief — semantic Pi insertion evidence v1

## Trigger

Decision 82/r24 solved the digest `preimage_kind` defect, but implementation task `4278` proved the protocol still did not determine one schema/edge/fixture compiler. Decision 84 task `4298` attempted an exhaustive correction. AK evidence `5492` records that the surface expands to at least 155 schemas and 2,591 root properties before nested shapes; four catalog attempts did not converge or produce machine-executable source.

Repeated local corrections are therefore not a truthful path to implementation. The protocol mixed a narrow Pi-host observation need with production authorization, recovery, replay stores, owner appointments, SQL, seccomp, Wasm, generic resolver graphs, and future consumer authority.

## Required outcome

Define a new compact protocol that proves only this bounded observation:

> The Pi host assigned and read back a prompt chain containing the exact contribution returned by `pi-ontology-workflows`, then completed the same contributor's restricted acknowledgement callback before provider/model dispatch became eligible.

The protocol must:

1. use repository `pi-extensions`, component `pi-ontology-workflows`, and package `@tryinget/pi-ontology-workflows`;
2. use a host-private, attempt-scoped, one-use witness rather than serialized identity as live authority;
3. bind input, contribution, assigned prompt chain, readback, execution generation, attempt, and handler index;
4. state that it proves neither provider transmission, model invocation, influence, semantic correctness, publication, adoption, activation, nor production delivery;
5. remain default-off and grant no implementation or dogfood authority before a superseding ADR and fresh owner tasks;
6. have at most seven named top-level protocol schemas and no generic resolver/edge registry.

## Historical boundary

Decision 53 v0 and Decisions 71, 80, 82, and 84 remain immutable history. Failed tasks `4230`, `4250`, `4278`, and `4298` and evidence `5325`, `5404`, `5446`, and `5492` remain non-authorizing. This redesign does not repair, reopen, or generate bytes for those protocols.

## Non-goals

No production receipt, semantic release overlay, consumer relation, owner appointment, live acquisition, replay database, recovery protocol, seccomp policy, WebAssembly ABI, packet resolver, publication, activation, default, installation/reload execution, or provider/model claim is in scope. Reload invalidation behavior is specified only to prevent stale witness use; this does not authorize performing a reload.

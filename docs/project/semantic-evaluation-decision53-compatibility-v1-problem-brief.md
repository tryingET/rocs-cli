# Decision 107 — compatibility-adapter problem brief

## Decision question

Can a non-authoritative adapter currently translate a ROCS semantic-evaluation result into Decision 53 compatibility, publication, currentness, or adoption inputs without creating meaning or authority?

## Controlling facts

1. Decision 53 is accepted. It separates semantic-owner meaning and publication, ROCS deterministic verification, consumer adoption, AK lineage, Pi delivery, and empirical analysis.
2. Decision 105 accepted one exact digest-only execution-custody projection. Its nonclaims include no semantic meaning, deterministic verdict, publication, currentness, adoption, or activation authority.
3. Decision 106 is complete with `outcome=rejected` and controlling review outcome `reject_current_direction`. The accepted Decision 105 projection contains no semantic-owner policy bytes, policy-selected subject preimages, typed joins, acquisition authority, verdict vocabulary, or precedence.
4. Decision 106 exposes no accepted semantic-evaluation output interface. Its controlling synthesis explicitly keeps Decision 107 blocked.
5. Before task 4626, Decision 107 had no artifacts or linked tasks and its declared RFC path did not exist.

## Architectural problem

An adapter transforms an existing typed fact; it does not create the source fact. Decision 107 currently has no accepted upstream semantic result, no accepted result vocabulary, and no mapping contract to Decision 53. Any adapter proposed now would have to do at least one forbidden thing:

- infer semantic meaning from opaque digests;
- rename identity or schema conformance as semantic evaluation;
- issue a permanent `not_evaluable` result as if Decision 106 had accepted it;
- invent semantic-owner policy, subjects, access rights, verdicts, or precedence;
- issue Decision 53 publication, currentness, compatibility, adoption, or activation facts outside their owners.

A narrow exact-byte or wire-conformance checker could report structural facts, but that is a different capability with different consumers and must use a new decision. It cannot repair Decision 107's absent semantic input.

## Required adjudication

Strict review must choose exactly one outcome:

- `ready_for_adr` only if an accepted semantic-evaluation source interface and lawful Decision 53 mapping already exist;
- `revise_rfc` if the packet has a material correctable defect or overlooked accepted interface;
- `reject_current_direction` if the source interface is absent and no adapter is constructible.

The requested outcome is `reject_current_direction`.

## Future boundary

Future semantic evaluation requires a new semantic-owner proposal with exact policy, subjects, acquisition authority, currentness, typed joins, and conformance vectors. A downstream Decision 53 adapter may be proposed only after that new upstream interface is accepted. Future evidence cannot retroactively convert Decision 106 or Decision 107 into accepted architecture.

## Non-authorization

This brief authorizes no implementation, ADR, semantic evaluation, wire adapter, data acquisition, ontology or DSPx mutation, provider/model/network use, publication, adoption, activation, dogfood, production, or push.
